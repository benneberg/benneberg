# Selected systems

### Insidr Management
**Edge observability & remote operations**

A platform for remotely diagnosing and managing locked-down Chromium-based
edge devices. Explores WebSocket-based telemetry, device state, remote diagnostics,
fleet operations and failure-aware observability without requiring direct
access to the device.

→ [Repository](https://github.com/benneberg/insidr-management)

---

### Nexus
**Systems engineering workspace**

A full-stack environment exploring deterministic state, event-driven
communication, repository intelligence and AI-assisted system interaction.
Built around control-plane/data-plane concepts, WebSocket streaming,
persistent client state, semantic repository analysis and server-side AI
integration.

→ [Repository](https://github.com/benneberg/nexus)

---

### ShadowFrame2
**Digital signage edge runtime laboratory**

A high-fidelity simulation environment for experimenting with signage
runtimes without requiring physical devices. Includes deterministic sequencing,
zero-gap A/B video playback, offline asset storage, device-state synchronization
and runtime telemetry.

→ [Repository](https://github.com/benneberg/shadowframe2)

# Digital Signage Systems

A recurring engineering thread in my work has been digital signage and
distributed edge systems. Rather than being a collection of unrelated projects,
several of these systems evolved from one problem space:

```text
                    CONTROL PLANE
                         │
                      OmniSign
                         │
                         ▼
                    EDGE RUNTIME
                       Shadow
                         │
                         ▼
                  RUNTIME LABORATORY
                    ShadowFrame
                         │
                         ▼
                 REMOTE OBSERVABILITY
                      Insidr
```

The work has explored:

* heterogeneous edge devices
* offline-first operation
* deterministic media playback
* device synchronization
* remote debugging and telemetry
* failure recovery
* fleet management
* hardware/runtime abstraction

This is where many of my ideas around reliability, observability and
distributed systems became practical engineering problems.

# Experimental ideas

Some of my projects start as engineering problems.
Others start with a question.

I'm particularly interested in exploring what happens when AI becomes part
of a larger system rather than simply a chatbot.

**AI Workforce OS** — Treating AI systems as organized workforces with roles, responsibilities, capabilities and accountability.

**Predixa** — Making advanced AI prediction capabilities understandable and actionable for non-technical business decision makers.

**Intent Runtime** — Exploring architectures where intent becomes a first-class input rather than simply a sequence of commands.

**Human–AI systems** — Investigating what becomes possible when AI is treated as a collaborator within a larger system.

*Not every experiment becomes a product.*
*That's part of the point.*
